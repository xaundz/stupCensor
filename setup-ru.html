Коротко

Аддон добавляет в меню трека (три точки) пункты «Найти без цензуры» и «stupidCensor: открыть», а также помечает заменённые треки значком SC. Он не хранит музыку на стороннем сервере: поиск и публикация выполняются в вашем публичном GitHub-репозитории через GitHub Actions, а готовая запись попадает в Releases. Добавления друзей проходят через GitHub Issues и публикуются только после подтверждения владельцем.

Что делает аддон

  • Ищет альтернативные записи на YouTube и SoundCloud.
  • Показывает кандидатов и скачивает только выбранную запись.
  • Публикует выбранный файл в ваш GitHub Releases.
  • Записывает замену в list.json.
  • Автоматически регистрирует подмену по ID трека.

Что нужно понимать

  • Владельцу нужен публичный репозиторий и GitHub-токен. Друзьям для чтения токен не нужен; для добавления — свой токен и подтверждение владельцем.
  • Автопроверка не определяет цензуру: проверяйте источник.
  • YouTube может требовать cookies с IP GitHub Actions; для ручной ссылки доступны YouTube и SoundCloud.
  • Публикуя аудио, вы отвечаете за авторские права. Публикуйте только записи, на которые у вас есть права.
  • Приватный репозиторий не подойдёт.

Шаг 1. Публичный репозиторий

  1. Создайте репозиторий Откройте github.com/new. Выберите Public, имя на ваш вкус, например uncensor-cloud. Приватный репозиторий не подходит: Яндекс Музыке нужны прямые публичные ссылки на аудио.
  2. Скопируйте облачные файлы В корень репозитория положите: 
    list.json
.github/workflows/uncensor-cloud.yml
.github/workflows/uncensor-approve.yml
cloud/uncensor_worker.py
cloud/requirements.txt
    Их можно загрузить через веб-интерфейс GitHub (Add file → Upload files) или через git: 
    git init
git remote add origin https://github.com/ВАШ_ЛОГИН/uncensor-cloud.git
git add .
git commit -m "Uncensor Cloud cloud files"
git push -u origin main
    Для пустого индекса используйте: 
    {
  "schema": 1,
  "name": "Uncensor Cloud",
  "tracks": {}
}
  3. Включите Actions и запись Откройте вкладку Actions, разрешите workflows. Убедитесь, что в списке есть Uncensor Cloud и Uncensor Cloud Approval и оба активны. Затем в Settings → Actions → General → Workflow permissions выберите Read and write permissions: без этого встроенный токен не сможет обновить list.json, Releases и Issues.
  4. Проверьте ветку Оба workflow должны лежать в ветке по умолчанию (main), иначе GitHub не покажет их в списке, а approval workflow не сможет найти заявку. Аддон запускает задания в ветке по умолчанию.
Почему нужен публичный репозиторий Аудио воспроизводится по ссылке GitHub Releases. Если репозиторий приватный, ссылка потребует авторизацию и плеер не сможет открыть файл.

Шаг 2. GitHub-токен владельца

Вариант A: fine-grained token

  1. Откройте создание fine-grained token.
  2. Resource owner — ваш аккаунт или организация-владелец репозитория.
  3. Repository access — Only select repositories → нужный репозиторий.
  4. Permissions: Contents: Read and write, Actions: Read and write, Issues: Read and write, Metadata: Read (Metadata обычно включён обязательно). Для локальной загрузки заявок и сохранения cookies/прокси из аддона нужен Issues: Read and write; для секретов также добавьте Secrets: Read and write.
  5. Срок действия — на ваше усмотрение. Скопируйте токен: он показывается один раз.

Вариант B: классический token

Создайте token на github.com/settings/tokens и отметьте:

  • repo — доступ к Contents и приватным данным (даже для публичного репозитория);
  • workflow — запуск GitHub Actions.

Токен друга

Другу не нужен токен для чтения библиотеки. Если он хочет добавлять треки, создайте отдельный fine-grained token с доступом только к этому репозиторию:

  • Actions: Read and write — запуск поиска и заявки.
  • Contents: Read — чтение list.json и статусов.
  • Metadata: Read — обязательный базовый доступ.

Не выдавайте другу Contents: Read and write: такой collaborator сможет обойти проверку и изменить файлы напрямую через сайт GitHub. Заявки друзей создаются от имени GitHub Actions, поэтому Issues: write приложению не нужен.

Не публикуйте токен Токен хранится только в локальном хранилище аддона, если включена галочка «Хранить токен». Он не должен попадать в list.json, jobs, workflow inputs, README, скриншоты или архив. При утечке отзовите его в настройках GitHub.

Шаг 3. Установка аддона

  1. Установите папку аддона В архиве возьмите папку stupid-censor и скопируйте её в каталог аддонов PulseSync. Альтернатива: установите ZIP через интерфейс клиента, если ваша версия это поддерживает.
  2. Перезапустите PulseSync После установки откройте Яндекс Музыку внутри PulseSync. В меню трека (три точки) появятся «Найти без цензуры» и «stupidCensor: открыть».
  3. Проверьте настройки В настройках аддона можно отключить меню stupidCensor и автоприменение библиотеки.
Кнопки нет Проверьте: аддон включён, версия PulseSync поддерживает WebHost-аддоны, в metadata указан правильный directoryName. Старые сборки PulseSync без WebHost не смогут загрузить этот аддон.

Шаг 4. Подключение GitHub

  1. Откройте раздел Откройте меню трека (три точки) → «stupidCensor: открыть», затем перейдите на вкладку «GitHub».
  2. Укажите репозиторий Формат: владелец/репозиторий или полная ссылка https://github.com/владелец/репозиторий.
  3. Вставьте токен Токен нужен для запуска workflow и чтения служебных файлов. Если снять «Хранить токен», после перезапуска останется режим чтения: библиотека работает, новые задания не запускаются.
  4. Нажмите «Подключить» Аддон проверит, что репозиторий публичный, workflow существует и активен. При успехе появится сообщение с именем репозитория и веткой.
Друзьям токен не нужен Нажмите «Подключить общую библиотеку» — аддон подключит xaundz/stupidcensor-cloud в режиме чтения. Друзья увидят замены владельца и смогут скрывать их только у себя. Для добавления треков нужен личный токен с Actions: Read and write и Contents: Read; collaborator-доступ не обязателен, а удаление из GitHub всё равно блокируется аддоном.

Шаг 5. Как пользоваться

Поиск

  1. Откройте меню трека → «Найти без цензуры». Уверенное совпадение сохранится автоматически, иначе откроется панель для подтверждения.
  2. Проверьте исполнителя, название и длительность.
  3. При необходимости вставьте конкретную страницу поддерживаемого источника.
  4. Нажмите «Найти замену».
  5. Дождитесь статуса «Кандидаты»: задание продолжится, даже если закрыть панель.

Проверка и публикация

  1. Откройте страницу кандидата и проверьте запись.
  2. Убедитесь, что это не кавер, не ремикс и не цензурированная копия.
  3. Нажмите «Сохранить» (владелец) или «На проверку» (друг).
  4. Владелец скачивает запись сразу. Заявка друга ждёт кнопку «Принять» в панели владельца.
  5. Дождитесь статуса «Опубликовано»: библиотека обновится, замена применится.

Ручное добавление

Раздел «Добавить свою ссылку» принимает прямую HTTPS-ссылку на файл (m4a, mp3, aac, ogg, opus, flac, wav) или страницу источника: YouTube или SoundCloud. Ссылка должна быть постоянной: без X-Amz-Signature, token, expires и других временных параметров. Проверьте файл в браузере перед публикацией: аддон не анализирует содержимое. У друга ссылка тоже попадает в заявку и публикуется только после подтверждения владельцем.

Для YouTube-страницы нужны cookies в секрете YTDLP_COOKIES; без них GitHub Actions обычно получает youtube_auth.

Заявки друзей

Друг с токеном добавляет трек так же, как владелец, но worker не скачивает аудио. Вместо этого он создаёт Issue с меткой uncensor-request и файл submissions/<job_id>.json. Владелец открывает «Заявки» в настройках аддона или Issues репозитория и принимает решение:

  • uncensor-local — кнопка «Принять» в аддоне. Локальный помощник на компьютере владельца скачивает запись, загружает M4A в Releases, обновляет list.json и удаляет временные файлы.
  • uncensor-approved — запасной вариант: GitHub Actions скачивает запись на сервере. Используется, если локальный помощник выключен.
  • uncensor-rejected — worker удаляет submission и закрывает Issue без публикации.

Локальный помощник запускается из архива stupidcensor-local-helper в GitHub Releases: установите ffmpeg, сохраните токен владельца и запустите start-local-publisher.command. Cookies YouTube помощник читает из браузера локально, в GitHub их отправлять не нужно. Если загрузка не удалась, помощник пишет причину в Issue, снимает uncensor-local и оставляет заявку открытой для повтора.

Отклонять и подтверждать может только владелец репозитория; остальные получат отказ. Друзьям не нужно скачивать YouTube: они получают уже готовый файл из Releases.

Библиотека и задания

  • Библиотека — все записи из list.json; можно включить, выключить, открыть трек или скрыть связь.
  • Задания — статусы поиска, публикации, переключения, удаления и заявок («На проверке»). Журнал Actions и кнопка «Заявки» видны владельцу.
  • Массовый поиск — запускает поиск для треков текущей очереди, до 10 за раз.
  • Удалить (владелец) убирает связь из индекса и аудиофайлы трека из Releases. Остальные могут только скрыть замену у себя.
  • Текущий трек можно перезапустить, если подмена не слышна сразу.
Проверка результата После публикации откройте текущий трек заново. Если он играл, аддон попробует перезагрузить плеер; иначе перезапустите трек вручную.

Шаг 6. YouTube: вход, cookies и прокси

С IP GitHub Actions YouTube часто требует вход: worker получает Sign in to confirm you're not a bot. В настройках аддона можно открыть вход в браузере, но аддон не имеет доступа к cookies браузера и не может получить их автоматически. После входа экспортируйте cookies в формате Netscape, выберите файл в аддоне или вставьте содержимое текстом. Cookies — это доступ к аккаунту Google, поэтому используйте отдельный аккаунт.

Cookies — это доступ к аккаунту Google Не вставляйте cookies в Issue, README или файлы публичного репозитория. Поле в аддоне нужно только для передачи значения в секрет; аддон не сохраняет его локально. Секрет YTDLP_COOKIES передаётся в workflow как переменная окружения и не попадает в inputs и логи. Если cookies попали в публичное место — завершите сессии Google и экспортируйте новые.
  1. В аддоне откройте «GitHub» → «YouTube: cookies и прокси» и нажмите «Войти в YouTube». Войдите в отдельный аккаунт, который не жалко использовать для автоматизации.
  2. Установите расширение Get cookies.txt LOCALLY (Chrome/Edge/Firefox) и экспортируйте cookies только для youtube.com в формате Netscape. Альтернатива для опытных: команда yt-dlp --cookies-from-browser chrome --cookies cookies.txt --skip-download "https://www.youtube.com/watch?v=BaW_jenozKc".
  3. В аддоне выберите файл cookies.txt или вставьте его содержимое в поле «Или вставить cookies текстом». Если токену добавлено право Secrets: Read and write, нажмите «Загрузить cookies в GitHub». Без этого права откройте репозиторий → Settings → Secrets and variables → Actions → New repository secret, имя YTDLP_COOKIES, значение — содержимое файла. Если GitHub не принимает многострочное значение, выполните на macOS (printf 'base64:'; base64 -i cookies.txt) | pbcopy и вставьте результат.
  4. Нажмите «Проверить YouTube». Проверка требует реальные cookies входа (SAPISID или LOGIN_INFO) либо настроенный прокси. Результат появится здесь и в «Заданиях»: «YouTube доступен» или ошибка youtube_auth/cookies_invalid.
Почему нельзя войти прямо в аддоне PulseSync-аддон работает в sandbox и не имеет доступа к cookies браузера или Electron-сессии. Кнопка входа открывает обычный браузер, но после входа всё равно нужен экспорт файла. Это ограничение платформы, а не ошибка настройки.

Если блокировка по IP

Иногда cookies не помогают, потому что YouTube блокирует адрес GitHub Actions. В разделе «Прокси для загрузки» укажите полный адрес http://user:pass@host:port, https://host:port или socks5://host:port и нажмите «Сохранить прокси в GitHub». Аддон проверяет адрес, маскирует ввод, шифрует значение и сохраняет его в YTDLP_PROXY; локальные и служебные адреса отклоняются. Для сохранения из аддона нужно право Secrets: Read and write. Прокси должен разрешать исходящие соединения к YouTube; он тоже может быть заблокирован.

SoundCloud

Для новых поисков доступны YouTube и SoundCloud. SoundCloud-треки с DRM помечаются как недоступные; выберите другую запись. Прямая HTTPS-ссылка на аудиофайл тоже поддерживается.

Если что-то не работает

Кандидаты не найдены

Измените название/исполнителя, уберите лишние слова, укажите длительность или конкретную страницу поддерживаемого источника. Проверьте журнал Actions: возможно, источник ответил 403 или потребовал вход. Для YouTube загрузите cookies и/или прокси в настройках аддона и нажмите «Проверить YouTube». SoundCloud-треки с DRM скачать нельзя — аддон помечает их как недоступные и предлагает выбрать другую запись.

Задание зависло в очереди

Откройте вкладку Actions в репозитории. Workflow может ждать свободный runner или не запускаться из-за отключённых Actions. Аддон через ~20 секунд попробует найти запуск, а через 2 минуты без запуска покажет ошибку. Через 45 минут задание считается истёкшим. Зависшее задание можно отменить во вкладке «Задания».

Ошибка 403 или «исчерпан лимит»

Проверьте права токена: Contents Read and write, Actions Read and write. Для классического token — repo и workflow. Лимит GitHub API сбрасывается через час; подождите или используйте другой токен.

Заявка друга не публикуется

Проверьте, что Issue открыт и содержит метку uncensor-request. Для локальной загрузки должна быть метка uncensor-local, а на компьютере владельца запущен start-local-publisher.command. Для запасного варианта через GitHub Actions нужна метка uncensor-approved и включённый approval workflow. Если публикация упала, в Issue появится комментарий с ошибкой; исправьте причину и примите заявку снова.

Подмена не слышна

Перезапустите текущий трек. Убедитесь, что связь включена в «Библиотеке» и файл доступен по ссылке. Иногда плееру нужен полный reload. Нажмите «Проверить файл» в карточке трека.

list.json не найден

Добавьте файл в корень ветки по умолчанию или дайте worker создать его первой публикацией. После добавления нажмите «Обновить» в библиотеке.

Репозиторий отклонён

Он приватный, workflow отсутствует/выключен или токен не имеет прав. Проверьте раздел «Состояние подключения» и журнал Actions. Приватные репозитории не поддерживаются намеренно.

Задание долго выполняется

Поиск обычно занимает меньше минуты, публикация — до двух минут. Если запуск завис, откройте «Задания» и нажмите «Отменить». В релизе library хранится один файл на трек: прежние версии удаляются при публикации, а файл удалённой связи удаляется вместе с ней.

Ограничения и честность

Автоматическая проверка не ищет цензуру Аддон сравнивает название, исполнителя и длительность. Он не анализирует текст, не находит вырезанные фрагменты и не гарантирует, что запись не является кавером, ремиксом или другой версией. Финальное решение — за пользователем.
  • Источники могут быть недоступны с IP GitHub Actions или требовать cookies/вход. Для YouTube загрузите YTDLP_COOKIES и/или YTDLP_PROXY в настройках аддона и проверьте доступ. SoundCloud с DRM не скачивается — это внешнее ограничение, а не ошибка аддона.
  • Поиск не скачивает аудио. Файл скачивается и перекодируется в M4A/AAC 160 kbps только после подтверждения; качество зависит от источника.
  • GitHub Releases и Actions имеют лимиты аккаунта. Большие библиотеки требуют места.
  • Публичный репозиторий означает публичные ссылки и имена файлов. Не добавляйте токены и личные данные в публичные файлы.
  • Публикуйте только записи, на которые у вас есть права. Аддон не проверяет авторские права и правила GitHub.
  • Аддон не обходит DRM, авторизацию, платный доступ или технические ограничения сервисов.
  • Запрет удаления действует внутри аддона и worker. Collaborator с правом Contents write всё ещё может удалить файл или обойти approval через сайт GitHub; не выдавайте друзьям такой доступ.
  • Ответственность за загруженные аудиофайлы и соблюдение авторских прав несёт владелец репозитория.
  • Токен в локальном хранилище аддона может быть доступен другим процессам с доступом к профилю PulseSync. Используйте отдельный токен с минимальными правами и сроком действия.
