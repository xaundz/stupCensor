Коротко

Аддон добавляет в меню трека (три точки) пункты «Найти без цензуры» и «stupidCensor: открыть», а также помечает заменённые треки значком SC. Он не хранит музыку на стороннем сервере: поиск и публикация выполняются в вашем публичном GitHub-репозитории через GitHub Actions, а готовая запись попадает в Releases.

Что делает аддон

  • Ищет альтернативные записи на YouTube и SoundCloud.
  • Показывает кандидатов и скачивает только выбранную запись.
  • Публикует выбранный файл в ваш GitHub Releases.
  • Записывает замену в list.json.
  • Автоматически регистрирует подмену по ID трека.

Что нужно понимать

  • Нужен публичный репозиторий и GitHub-токен.
  • Автопроверка не определяет цензуру: проверяйте источник.
  • YouTube/SoundCloud могут блокировать IP GitHub Actions.
  • Публикуя аудио, вы отвечаете за авторские права. Публикуйте только записи, на которые у вас есть права.
  • Приватный репозиторий не подойдёт.

Шаг 1. Публичный репозиторий

  1. Создайте репозиторий Откройте github.com/new. Выберите Public, имя на ваш вкус, например uncensor-cloud. Приватный репозиторий не подходит: Яндекс Музыке нужны прямые публичные ссылки на аудио.
  2. Скопируйте облачные файлы В корень репозитория положите: 
    list.json
.github/workflows/uncensor-cloud.yml
cloud/uncensor_worker.py
cloud/requirements.txt
    Их можно загрузить через веб-интерфейс GitHub (Add file → Upload files) или через git: 
    git init
git remote add origin https://github.com/ВАШ_ЛОГИН/uncensor-cloud.git
git add .
git commit -m "Uncensor Cloud cloud files"
git push -u origin main
    Для пустого индекса используйте: 
    {
  "schema": 1,
  "name": "Uncensor Cloud",
  "tracks": {}
}
  3. Включите Actions и запись Откройте вкладку Actions, разрешите workflows. Убедитесь, что в списке есть Uncensor Cloud и он активен. Затем в Settings → Actions → General → Workflow permissions выберите Read and write permissions: без этого встроенный токен не сможет обновить list.json и Releases.
  4. Проверьте ветку Workflow должен лежать в ветке по умолчанию (main), иначе GitHub не покажет его в списке. Аддон запускает workflow в ветке по умолчанию.
Почему нужен публичный репозиторий Аудио воспроизводится по ссылке GitHub Releases. Если репозиторий приватный, ссылка потребует авторизацию и плеер не сможет открыть файл.

Шаг 2. GitHub-токен

Вариант A: fine-grained token

  1. Откройте создание fine-grained token.
  2. Resource owner — ваш аккаунт или организация-владелец репозитория.
  3. Repository access — Only select repositories → нужный репозиторий.
  4. Permissions: Contents: Read and write, Actions: Read and write, Metadata: Read (Metadata обычно включён обязательно).
  5. Срок действия — на ваше усмотрение. Скопируйте токен: он показывается один раз.

Вариант B: классический token

Создайте token на github.com/settings/tokens и отметьте:

  • repo — доступ к Contents и приватным данным (даже для публичного репозитория);
  • workflow — запуск GitHub Actions.
Не публикуйте токен Токен хранится только в локальном хранилище аддона, если включена галочка «Хранить токен». Он не должен попадать в list.json, jobs, workflow inputs, README, скриншоты или архив. При утечке отзовите его в настройках GitHub.

Шаг 3. Установка аддона

  1. Установите папку аддона В архиве возьмите папку stupid-censor и скопируйте её в каталог аддонов PulseSync. Альтернатива: установите ZIP через интерфейс клиента, если ваша версия это поддерживает.
  2. Перезапустите PulseSync После установки откройте Яндекс Музыку внутри PulseSync. В меню трека (три точки) появятся «Найти без цензуры» и «stupidCensor: открыть».
  3. Проверьте настройки В настройках аддона можно отключить меню stupidCensor и автоприменение библиотеки.
Кнопки нет Проверьте: аддон включён, версия PulseSync поддерживает WebHost-аддоны, в metadata указан правильный directoryName. Старые сборки PulseSync без WebHost не смогут загрузить этот аддон.

Шаг 4. Подключение GitHub

  1. Откройте раздел Откройте меню трека (три точки) → «stupidCensor: открыть», затем перейдите на вкладку «GitHub».
  2. Укажите репозиторий Формат: владелец/репозиторий или полная ссылка https://github.com/владелец/репозиторий.
  3. Вставьте токен Токен нужен для запуска workflow и чтения служебных файлов. Если снять «Хранить токен», после перезапуска останется режим чтения: библиотека работает, новые задания не запускаются.
  4. Нажмите «Подключить» Аддон проверит, что репозиторий публичный, workflow существует и активен. При успехе появится сообщение с именем репозитория и веткой.

Шаг 5. Как пользоваться

Поиск

  1. Откройте меню трека → «Найти без цензуры». Уверенное совпадение сохранится автоматически, иначе откроется панель для подтверждения.
  2. Проверьте исполнителя, название и длительность.
  3. При необходимости вставьте конкретную страницу YouTube/SoundCloud.
  4. Нажмите «Искать в облаке».
  5. Дождитесь статуса «Кандидаты»: задание продолжится, даже если закрыть панель.

Проверка и публикация

  1. Откройте страницу кандидата и проверьте запись.
  2. Убедитесь, что это не кавер, не ремикс и не цензурированная копия.
  3. Нажмите «Сохранить».
  4. Аддон скачает и перекодирует только выбранную запись.
  5. Дождитесь статуса «Опубликовано»: библиотека обновится, замена применится.

Ручное добавление

Раздел «Добавить свою ссылку» принимает прямую HTTPS-ссылку на файл (m4a, mp3, aac, ogg, opus, flac, wav). Страница YouTube/SoundCloud не подойдёт. Ссылка должна быть постоянной: без X-Amz-Signature, token, expires и других временных параметров. Проверьте файл в браузере перед публикацией: аддон не анализирует содержимое.

Библиотека и задания

  • Библиотека — все записи из list.json; можно включить, выключить, открыть трек или скрыть связь.
  • Задания — статусы поиска, публикации, переключения и удаления. Ссылка Actions ведёт в журнал.
  • Удалить скрывает связь в индексе. Аудиофайл в Releases остаётся доступным.
  • Текущий трек можно перезапустить, если подмена не слышна сразу.
Проверка результата После публикации откройте текущий трек заново. Если он играл, аддон попробует перезагрузить плеер; иначе перезапустите трек вручную.

Если что-то не работает

Кандидаты не найдены

Измените название/исполнителя, уберите лишние слова, укажите длительность или конкретную страницу YouTube/SoundCloud. Проверьте журнал Actions: возможно, источник ответил 403 или потребовал вход. IP GitHub Actions часто блокируется YouTube.

Задание зависло в очереди

Откройте вкладку Actions в репозитории. Workflow может ждать свободный runner или не запускаться из-за отключённых Actions. Аддон через ~20 секунд попробует найти запуск, а через 2 минуты без запуска покажет ошибку. Через 30 минут задание считается истёкшим. Зависшее задание можно отменить во вкладке «Задания».

Ошибка 403 или «исчерпан лимит»

Проверьте права токена: Contents Read and write, Actions Read and write. Для классического token — repo и workflow. Лимит GitHub API сбрасывается через час; подождите или используйте другой токен.

Подмена не слышна

Перезапустите текущий трек. Убедитесь, что связь включена в «Библиотеке» и файл доступен по ссылке. Иногда плееру нужен полный reload. Нажмите «Проверить файл» в карточке трека.

list.json не найден

Добавьте файл в корень ветки по умолчанию или дайте worker создать его первой публикацией. После добавления нажмите «Обновить» в библиотеке.

Репозиторий отклонён

Он приватный, workflow отсутствует/выключен или токен не имеет прав. Проверьте раздел «Состояние подключения» и журнал Actions. Приватные репозитории не поддерживаются намеренно.

Задание долго выполняется

Поиск обычно занимает меньше минуты, публикация — до двух минут. Если запуск завис, откройте «Задания» и нажмите «Отменить». Старые аудиофайлы в релизе library при удалении связи не стираются: их можно удалить вручную на странице Releases.

Ограничения и честность

Автоматическая проверка не ищет цензуру Аддон сравнивает название, исполнителя и длительность. Он не анализирует текст, не находит вырезанные фрагменты и не гарантирует, что запись не является кавером, ремиксом или другой версией. Финальное решение — за пользователем.
  • Источники YouTube/SoundCloud могут быть недоступны с IP GitHub Actions или требовать cookies/вход. Это внешнее ограничение, а не ошибка аддона.
  • Поиск не скачивает аудио. Файл скачивается и перекодируется в M4A/AAC 160 kbps только после подтверждения; качество зависит от источника.
  • GitHub Releases и Actions имеют лимиты аккаунта. Большие библиотеки требуют места.
  • Публичный репозиторий означает публичные ссылки и имена файлов. Не добавляйте токены и личные данные в публичные файлы.
  • Публикуйте только записи, на которые у вас есть права. Аддон не проверяет авторские права и правила GitHub.
  • Аддон не обходит DRM, авторизацию, платный доступ или технические ограничения сервисов.
  • Ответственность за загруженные аудиофайлы и соблюдение авторских прав несёт владелец репозитория.
  • Токен в локальном хранилище аддона может быть доступен другим процессам с доступом к профилю PulseSync. Используйте отдельный токен с минимальными правами и сроком действия.
